# 第 4 阶段：交接

在需求阶段 plan 写入之后，或 Lightweight 以对话中的一段话结束、不需要文件之后读取。需要文件才能执行的选项在没有文件时自动隐藏；两种情况都呈现交接。

---

## 4.1 呈现下一步选项

### 先处理 Resolve Before Planning

Outstanding Questions 中有 `Resolve Before Planning` 项时：
* 现在就提出这些阻塞问题，按提问规则合并（互不依赖的每轮最多 3 个）；
* 用户明确要求先继续时，先把每个剩余项转成明确的决定、假设或 `Deferred to Planning` 问题；
* 用户选择暂停时，按"暂停"呈现交接，而不是"完成"；
* 仍有 `Resolve Before Planning` 项时，不显示"继续规划"选项。

### 选项

只显示适用的选项，编号连续从 1 开始：

1. **继续规划** *(Recommended)*——在本会话中用 `nk-plan` 把需求补充为完整、可测试的实施方案。仅在 `Resolve Before Planning` 为空时显示。
2. **换个视角自查需求**——以全新视角通读需求阶段 plan，找缺口、矛盾、站不住的前提和范围问题（见 4.2）。仅在已写入文件时显示。
3. **继续澄清范围**——通过更多对话细化范围、边界情况、约束和偏好。总是显示（选项名说的是范围而不是文档，在没写文件时同样成立）。
4. **结束会话**——按 `../../nk-handoff/SKILL.md` 更新 `docs/current.md` 并提交，下一个会话从 `current.md` 接手。总是显示。

可见选项数不超过当前客户端阻塞式提问工具的上限时用该工具（按能力匹配，不按工具名）；超过时在对话中渲染为编号列表，并提示"选一个编号，或直接说你想做什么"。不要静默跳过。

### 开场白

没有阻塞问题时：

```
头脑风暴完成。

Plan 文件：<需求阶段 plan 的绝对路径>        # 没有写文件时省略此行

规划将以这份文件作为"要做什么"的定义。     # 没有写文件时省略此行

接下来想做什么？
```

有阻塞问题、用户想暂停时：

```
头脑风暴已暂停。剩下的问题解决之前，我先不进入规划——你说一声我就继续，把每个未决项记为明确的假设或推迟到规划中回答的问题。

Plan 文件：<需求阶段 plan 的绝对路径>        # 没有写文件时省略此行

接下来想做什么？
```

"你说一声我就继续"这句是必要的：阻塞问题存在时"继续规划"被隐藏，没有这句话，用户只知道规划被卡住，却不知道解除阻塞的决定权在自己。`Resolve Before Planning` 是 Agent 的判断，过于谨慎的判断不能让用户无路可走。隐藏选项只是撤回**推荐**，从不撤回**选择**。

对话中引用文件时用绝对路径，便于在终端中点击。

## 4.2 处理所选选项

选择可能是选项名（或近似说法）或编号，编号对照当前实际渲染的列表。不匹配任何选项、也没描述其他动作的自由输入，当作澄清处理——追问，不要猜。

**继续规划：** 在本会话中读取 `../../nk-plan/SKILL.md` 并按其执行。有文件时传入 plan 路径；没有文件时传入对话中定下的决定摘要。1.1 的依据档案仍存在时，一并传入其路径——规划可以直接从带 `file:line` 的核实引用开始，不必重新扫描仓库。不先输出结束摘要。本次产出不提交，留在工作区（见 SKILL.md"不提交"）。

**换个视角自查需求：** 支持子代理时，派发一个没看过对话的子代理通读 plan；否则由主会话以审阅者身份重读。依次检查：
* **连贯性**：各节之间、需求之间有无矛盾，同一规则是否在多处写全；
* **可行性**：有没有依赖未核实的前提、与已知代码现状冲突的断言；
* **范围**：有没有周边工作渗入当前需求，有没有应列入非目标却没写的诱人项；
* **规划可用性**：规划者会不会被迫发明行为、参与者或成功标准。

只保留有项目证据支撑、且不改就会产生实际后果的问题；审阅意见本身不构成修改理由。不改变已定意图的修正直接就地改好；需要用户选择产品行为或范围的，按提问规则提问。完成后重跑 Ready for Planning Check，回到 4.1 重新渲染选项（需求可能变了，重新评估 `Resolve Before Planning`）。不先输出结束摘要。

**继续澄清范围：** 回到 1.3 继续对话，细化范围、边界情况、约束和偏好，直到用户满意，再回到第 4 阶段。不先输出结束摘要。

**结束会话：** 输出 4.3 的结束摘要，然后读取 `../../nk-handoff/SKILL.md` 按其执行：更新 `docs/current.md`（下一步写"用 `nk-plan` 规划 <plan 路径>"，或暂停时写阻塞问题），并把本会话的规划产出（plan 文件、`CONCEPTS.md`）与 `current.md` 合为一次提交。

**用户表示已经结束**（说"好了""就这样"，或关闭了选项而未选择）：按"结束会话"处理。

## 4.3 结束摘要

仅在本次流程结束或交接时使用，回到 4.1 选项时不用。

可以进入规划时：

```text
头脑风暴完成！

Plan 文件：<需求阶段 plan 的绝对路径>        # 没有写文件时省略此行

关键决定：
- [决定 1]
- [决定 2]

已写入 CONCEPTS.md：[本次新增或完善的术语]   # 没有时省略此行

建议下一步：`nk-plan <plan 路径>`              # 没有文件时：以上述关键决定为输入运行 `nk-plan`
```

有尚待用一次性原型回答的问题（提问规则第 7 条）时，在建议下一步中注明："规划时把 <问题> 作为首个原型单元。"

`Resolve Before Planning` 仍有未决项、用户暂停时：

```text
头脑风暴已暂停。

Plan 文件：<需求阶段 plan 的绝对路径>        # 没有写文件时省略此行

规划卡在：
- [阻塞问题 1]
- [阻塞问题 2]

用 `nk-brainstorm` 接着解决这些问题——或者直接说"先规划"，我会把每个未决项记为明确的假设或推迟到规划中回答的问题。
```
