# 合并、去重与复核

第 5 步读取本文件。输入是各 reviewer 返回的 JSON；输出是定稿的条目集。两部分：先合并去重，再独立复核。

## 一、合并与去重（规则转写自原 findings 机制脚本）

**字段校验**：不符合契约的 finding 直接丢弃并计数（缺必填字段、severity 不在 P0-P3、confidence 不在 0/25/50/75/100、evidence 为空、line 缺失）。丢弃数写入覆盖说明，不静默吞掉。

**去重指纹**：`(file 小写, line, title 归一化小写)` 相同的多条 finding 合并为一条：

- 严重级别取最高，置信度取最高；`reviewers` 并列署名全部命中者；
- `pre_existing` 只有全组一致为 true 才成立——当前 diff 相关的判定优先，精确重复不能因某 reviewer 先到而被错标为既有问题；
- 置信度 ≥ 75 但首条证据不含可引用的原文行（`file:line`）时，降为 50；
- `suggested_fix`、`requires_verification` 取并集（有一方为真/有值即保留）。

**置信度闸门**：

- 锚点 0 / 25：抑制，不进入任何产出（persona 本就不应发出；发出即视为校验失败丢弃）；
- 锚点 50：不进条目，除非 severity 为 P0（P0+50 保留并标注"未完全证实"）；其余 50 分关注并入当轮区块末尾的"测试缺口 / 残余风险"软清单；
- 锚点 75 / 100：成为正式条目。

**既有问题分区**：`pre_existing: true` 的合并结果不进条目流，单独列为"既有问题"小节（信息性，不占条目编号，不带置信度列）。

## 二、独立复核（validator）

复核者与产出 finding 的 reviewer、与做主会话合并者保持独立：支持子代理时派一个全新子代理；不支持时由主会话以"清空立场、只看证据"的方式重读。正常上限每批 8 条；存留的 P0/P1 超过 8 条时扩充同批覆盖全部 P0/P1，不因批次上限漏掉阻断项。

对每条存留 finding 给出三值判定：`confirmed` / `rejected` / `unresolved`。**不得以"无法证伪"作为证实依据。**

**受保护主题**（判定时先归类，关键词只触发检查、不构成保护）：memory-safety、concurrency、data-loss、authorization-authentication、injection、public-contract、secrets-exposure、cryptography。

- 受保护主题上，`rejected` 必须持有反驳证据之一：引用具体 `file:line` 反驳、指明在生效版本下的版本/配置文档、短哈希历史出处、或能区分真伪的测试结果（需说明被审版本、运行时版本、配置、触发的输入、断言与观察结果；笼统的"测试全绿"或未触及触发点的测试不算反驳）。没有这些证据时给 `unresolved`，不给 `rejected`。
- 非受保护主题保持普通证据标准：检查后不成立的拒绝并说明理由；应查而查不到（文件不可达、上下文缺失）一律 `unresolved` 并说明访问限制，不猜。
- 真实存在于代码但描述的状态可能从不发生：指明该缺陷成立所需的前置条件（输入、数据形态、时序），能及范围内取得可达性证据；够不着就在理由中注明"发生率未测量"，这不降低置信度、不阻断确认。
- 每条独立判定，不让一条的结果影响另一条；不发明新 finding。

**预算**：约 15 分钟、每条约 5 次工具调用；预算耗尽时剩余条目一律 `unresolved`，理由"预算耗尽，未检查"，不猜判定。

**判定落地**：`confirmed` -> 正式条目；`rejected` -> 剔除，在覆盖说明记一条原因；`unresolved` -> 保留为条目并在证据字段注明缺失的证据。

## 三、编号

复核定稿后一次性分配条目编号（`R<轮>-F<序>`，按 severity 排序连续编号），之后不再重排。编号规则详见 [`entry-format.md`](entry-format.md)。
