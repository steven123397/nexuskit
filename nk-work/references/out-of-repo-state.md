# 仓库外状态依赖与验证规范 (Out-of-Repo State)

本文件规范当实施单元的完成标志或验证流程依赖仓库外部状态时的处理机制与诚实验证原则。

---

## 一、什么是仓库外状态？

在工程实施中，部分特性的完整生效依赖代码仓库之外的基础设施或人工配置，例如：
* 云平台控制台设置（如 S3 存储桶跨域规则、环境变量注入、权限策略）；
* 第三方平台服务（如 OAuth 应用回调地址、Webhook 订阅、支付测试沙箱凭证）；
* 远程持久化数据库（如生产/测试库中的数据迁移、初始种子数据填充）；
* 域名与 DNS 解析记录。

---

## 二、处理原则与执行纪律

当单元包含仓库外状态依赖时，恪守以下纪律：

### 1. 仓库内工件先行闭环
* 必须在仓库内部将所有可静态落地的代码、配置模板（如 `.env.example`）、抽象接口与本地 Mock 单测全部完成；
* 单元测试必须在本地使用存根（Stub/Mock）验证完整的业务因果链，确保代码逻辑在模拟外部响应时 100% 通过。

### 2. 诚实记录验证边界（禁止虚报）
* 若由于权限缺失、离线环境或等待人类手动配置，导致无法真正连接外部环境进行端到端全链路验证：
  * **严禁声称“线上/集成已通过”**；
  * 在提交信息的验证证据正文中明确区分：
    ```text
    Verified: local unit tests with mocked oauth client (12/12 passed).
    Unverified: live OAuth provider token exchange (requires manual client secret setup).
    ```

### 3. 交接与阻断暴露
* 若外部配置未就绪导致后续工作无法推进，应立即在 `docs/current.md` 的 `## 阻断与已知缺口` 中进行显式登记（例如标注依赖的具体外部凭据或配置项），供后续拥有外部权限的开发者/会话接手处理。
