# 测试先行与质量设计 (Testing)

本文件规范测试驱动开发（TDD）中的好测试与坏测试辨别、测试 Seam 选择与 Mock 原则。

---

## 一、什么是测试接缝 (Seam)？

**接缝 (Seam)** 是可以在不修改业务代码内部实现的前提下，观察系统行为或改变系统行为的接入点（如公开函数、Trait、接口、API 端点）。

* **Agent 自选 Seam（K3）**：在规划与编码时，Agent 依据既有代码模式自主选择最自然的测试接缝，测试用例应当直接作用于接缝，而非探测私有变量。
* **何时向人类提问**：仅当选择的接缝会导致对外公开 API、协议契约发生变更，且落入 `conventions/decision-autonomy.md` 的确认区时，才向人类发起确认。

---

## 二、好测试 vs 坏测试

| 维度 | 好测试 (Good Tests) | 坏测试 (Anti-Patterns) |
| :-- | :-- | :-- |
| **测试目标** | 测试可观测的**行为与结果**（Behavior） | 测试内部实现细节、私有函数与私有状态 |
| **重构耐受力** | 只要行为不变，重构内部实现时测试**依然保持常绿** | 一旦重构内部辅助函数或变量名，测试立即大面积红掉 |
| **断言有效性** | 明确断言预期输出、返回状态或持久化结果 | 同义反复（Tautology）：用测试重新写了一遍业务代码算法 |
| **编写时序** | 垂直切片（Red $\to$ Green 循环） | 水平切片：先写出整套空测试再开始写实现 |
| **可读性** | 测试名称精确描述业务场景（Given-When-Then） | 测试名称模糊不清（如 `test_func_1`） |

## 三、Mock 模拟准则

过度 Mock 会导致“测试只测了 Mock 本身”，形成虚假的安全感。

### 1. 允许 Mock 的边界（系统外部边界）
仅在跨越不可控的系统外部环境时使用 Mock 或 Stub：
* 网络 HTTP 请求、第三方 API、远程 RPC；
* 操作系统时钟与时间敏感逻辑（如定时器、超时机制）；
* 耗时过长或具有破坏性的操作系统级调用（如格式化磁盘、直接调用云端费用 API）。

### 2. 禁止 Mock 的范围（系统内部逻辑）
* **禁止 Mock 同一模块内的内部函数与私有对象**；
* **禁止 Mock 纯计算业务领域逻辑**（数据转换、解析器、数学运算等一律直接用真实代码测试）；
* **禁止为了让测试通过而破坏业务类的封装性**。

### 3. 为可测试性设计 (Design for Testability)
若发现某个函数由于强绑定全局状态或硬编码外部调用而无法编写单元测试，应采用依赖注入（Dependency Injection）或将接口抽离为可插拔参数，使被测代码对测试保持透明。
