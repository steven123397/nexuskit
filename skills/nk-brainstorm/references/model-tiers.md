# 子代理分档

派发子代理（1.1 grounding 侦察、2.6 声明核实、需求自查的审阅者）前读取。按任务形态分档，不写死模型名：

* **提取档**——grounding 侦察：检索与引用。客户端支持按子代理指定模型、且知道对应名称时，用最便宜的够用模型。"够用"是要求的一部分：仓库很大或技术栈生僻时升到生成档。
* **生成档**——声明核实、需求自查：依据证据的核对工作。支持指定模型时用中档模型；不知道模型名称时不要猜，省略该设置、沿用会话模型。
* **最高档**——对话本身：提问、方案、综述和需求阶段 plan 都在主会话中用会话模型完成，不派发。

**降级规则：**
* 客户端的子代理机制不支持按子代理选择模型：用会话模型派发，保持同样的读取预算和产出上限——成本靠结构控制，而不是靠分档。
* 客户端没有子代理机制：在 1.1 内联完成主题扫描（依据档案仍写到临时目录，因为下游接收的是它的路径），并在第 3 阶段写入前内联核实断言，预算相同。
* 派发被拒绝时，按是否已经启动区分：启动前的参数错误修正一次；因容量受限的，排队等待；其他失败按上面的内联方式处理。
