# 正文引用自检清单

写完或重写 solution 条目后，逐项核对正文（frontmatter 之后的部分）中的事实性引用。此清单替代 CE 的 `validate-doc-claims.py`（脚本已删除）。

**每个标记都是裁决输入，不是错误**——记录"本次修复删除了某文件"的条目合法引用已不存在的路径。每个标记三选一：修正引用、标注为历史（如"已被本次修复删除"）、确认有意为之。

## 核对项

1. **引用的仓库路径**：正文中反引号包裹、含 `/` 的路径，逐一确认在工作树中存在；引用已删除文件时，确认上下文已标注其历史属性。
2. **提交 SHA**：以 commit 身份引用的十六进制串（"fixed in `<sha>`"、"commit `<sha>`"），确认 `git cat-file -e <sha>^{commit}` 可解析；只可达 HEAD 而不可达上游的 SHA 会被 rebase/squash 重写——改用 PR 编号。无法分类的十六进制串（会话 id、内容哈希）只在被当作 commit 引用时才需要处理。
3. **相对 Markdown 链接**：从条目所在位置解析，确认目标存在。
4. **草稿残留**："Learning 3"、"第 2 条"这类草稿编号、`{{...}}` 占位符——一律改成真实路径或链接（代码块或行内代码中作为语法示例出现的不算）。

## 行为断言复核

- 代码行为断言（枚举值、状态语义、限制、默认值）应有当前树的定义行支撑（`file:line`）；无支撑的软化或注明"按本次会话结论"，不写成事实。
- 合并状态断言（"已在 #N 修复/合并"）以远端为准（如 `gh pr view`，可先 `git fetch --quiet`，离线跳过）；查不了远端时保留断言并加"截至本文撰写"限定。
- 计数断言（"三个根因""全部 N 处"）与正文实际列举的数量一致。
