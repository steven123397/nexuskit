# 前端与 UI 改动验证要点 (UI Work)

本文件规范涉及用户界面（UI）、前端组件或页面布局改动时的专属走查要点。

---

## 一、布局与视口走查 (Viewports & Layout)

1. **响应式宽度检查**：
   * 必须在宽屏（桌面典型宽度 1280px+）与窄屏（移动端或紧凑侧边栏 375px~480px）下分别验证；
   * 确保无意外的水平横向滚动条；
   * 弹性盒（Flexbox）与网格（Grid）在收缩时能够正确换行或自适应缩放。
2. **文字溢出与多语言弹性**：
   * 检查长标题、长路径或长用户名是否引起容器撑破；
   * 确认设置了合理的文字截断规则（如 `text-overflow: ellipsis`）或折行策略（`word-break: break-word`）。

---

## 二、状态完整性 (Component States)

前端组件不能只在“有完整正常数据”的理想状态下验证，必须走查以下关键状态：

| 状态 | 验证要求 |
| :-- | :-- |
| **加载中 (Loading)** | 具有明确的加载占位符、骨架屏或 Spinner，防止界面闪烁或布局跳动 |
| **空数据 (Empty)** | 当列表为空或初次进入时，显示友好的空状态提示与行动引导 |
| **异常报错 (Error)** | 接口报错或数据损坏时，呈现可恢复的错误提示，避免白屏或未捕获的全局异常 |
| **交互态 (Interactive)** | Hover、Focus、Active、Disabled 状态视觉反馈清晰；禁用状态下阻断点击 |

---

## 三、视觉与控制台自检

1. **控制台日志**：在浏览器或 WebView 开发者工具中，确认控制台无未捕获的 JavaScript 错误、无 CSS 语法警告、无 React/Vue 渲染警告。
2. **实际预览**：若环境提供浏览器工具或本地 Dev Server，必须实际启动并预览真实渲染效果，避免纯凭静态代码臆测视觉呈现。
